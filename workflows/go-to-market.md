# Workflow: Go to Market

**Trigger:** positioning, channel choice, acquisition copy, measurement or execution for a pre-launch offer or a built product. Use `agents/go-to-market.md` for the diagnostic and specialist decisions.

For a smoke test, use the shared `workflows/test-demand.md`: Agent 1 owns the uncertainty and verdict, Agent 3 owns acquisition decisions, and Agent 2 owns the experience and implementation. A finished product and full PASS are not prerequisites for that bounded test.

---

## Steps

1. **Read memory.** Load the law, build rules, index, Agent 3 definition and relevant project records. Without an active folder, use the existing assessment/test record. Read Agent 1's evidence and what Agent 2 actually built.
2. **Orient briefly.** Confirm the offer, stage, customer starting point, near-term objective and existing authorizations. Reuse known traction, constraints and budgets; ask only for material missing inputs. Do not stop at another intake gate when the work is already requested.
3. **Make the GTM decisions.** Run the stage/market/network/awareness diagnostic and name the lead lens. Each panel lens raises a real concern/decision or clears its lane with a reason. Resolve conflicts explicitly. Select a primary channel by actual access, offer fit, economics and capacity. Record uncertainty rather than inventing an audience. For a follow-up, carry valid decisions forward and review affected ones.
4. **Prepare concrete assets.** Use Agent 3's six-part schema; for a smoke test, combine it compactly with the demand-test schema. Save in the existing output location. Produce the selected message, scripts/copy, measurement definitions and decision rules. Work with Agent 2 on design, working forms, data protection and instrumentation; verify promised availability against the actual build.
   Read the full product reference and its coverage record. A focused post may lead to the whole offer, but verify that its destination actually explains the accepted capabilities. Record gaps instead of treating an FAQ-only mention as complete representation.
5. **Execute the requested scope.** Where tools and authorization permit, carry out the acquisition actions and verify the result. Do not assume posting, messaging, ad spending or scheduling permission from asset preparation. Complete reviewable work before resolving missing authorization or access. A plan-only request stays at preparation.
6. **Write back.** Record positioning, diagnostic, panel decisions, channel bets, actual actions and results in the appropriate memory. Keep plans, execution and evidence separate. Without an active project, use the existing assessment/test record and a short index pointer. Do not assign `gtm-planned` to a whole product merely because a smoke-test package exists. Carry findings back to Agents 1 and 2 without restarting completed work.
